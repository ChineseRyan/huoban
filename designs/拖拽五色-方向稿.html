活板 · 拖拽五色 · 定稿 v2

拖文件进首屏：一团跟着鼠标的墨，颜色每次拖拽随机抽一支（朱 / 青 / 黛 / 赭 / 墨），标题写「请松手」。浅色与深色并列。2026-11-17 开发者逐条判过，文案定为「请松手」，松手不补判。

五色 · 浅色 / 深色

颜色不是装饰：四支取自封面配色里的印色，墨色是兜底。拖进来的东西被染成「它可能成为的那张纸」的颜色。

文案

文案定为「请松手」（2026-11-17 开发者定，原提的「松手即可」「请松手」备选作废）。

一、颜色从哪儿来（核实结果）

  • 界面变量里当时没有独立的青色。彼时的两档拖拽色只有印色与墨色两支 （--bloom-book 浅 168,58,46 / 深 214,94,77， --bloom-other 是墨色），都不是青；落地时这两支已由本稿的五色取代。
  • 但产品里已有「青」：封面的六套配色（gui/cover.py）的印色分别是 宣纸 #A83A2E、松墨 #C24A38、青瓷 #2C6C5F、靛蓝 #C8A02E、 赭石 #8E4B26、黛青 #35577D。开发者记到的「青色」应该就是这两支青。
  • 本稿取五支：朱（沿用现役印色）、青（青瓷）、黛（黛青）、赭（赭石）、墨（兜底）。 理由：这些颜色不是新造的，用户之后挑封面时会见到同一套；拖拽时随机抽一支， 像先摸到一张纸的印色，而不是换一套「随机装饰色」。
  • 深色一版各提亮一档，保证在 #15181D 上看得见；五色都比「纸」的亮度低（浅底）/ 高（深底）， 不会把标题压得看不清。

二、随机怎么随

  • 已定：同一拖拽内稳定——进入拖拽时抽一次，整段拖拽不换色；松开后颜色不跳， 随墨团一起淡出；下次拖拽重新抽。理由：拖拽中跳色像故障，也破坏「墨在洇」的连续感。
  • 未采纳：每 1.2 秒轮换（会闪）、按光标位置渐变（像荧光笔，与纸墨语言冲突）。

三、文案

  • 定为「请松手」（2026-11-17 开发者定）。方向稿 v1 里那句长文案与两个备选一并作废。

四、交接：悬停态到松手

  • 悬停期不再输出「书稿已得 / 非书也」，统一是「请松手」+ 五色墨团； 原来的 MIME 三档在悬停期退场（它本来就判不出 .lnk）。
  • 松手时沿用 0.2.3 第 2 条的机制：这个新态算「已表态」， 保持到 __onDropPath 到达、或 750ms 兜底到点；不会跳回「把书拖到这里」。
  • 松手后仍走现有流程：Python 报错进错误页，或正常进导入/忙碌页。
  • 和条目二不打架：条目二的定时器按状态名判断，新态加进「保持」集合即可，逻辑不变。

五、已判：松手不补判

  • 2026-11-17 定为不做：松手后不按后缀补一句「非书也 / 书稿已得」。
  • 「请松手」随墨团淡出，直接进现有流程：Python 该报错的报错、该导入的导入。

六、实现要点

  • 悬停期能用的信号只有：types:["Files"] 与 item.type （.txt→text/plain，.lnk→空）；文件名只有 drop 时可读（已实测）。
  • CSS：#drop-area 上换成一个内联写死的 --tone（rgb 三元组）与 --tone-solid； 删掉 [data-drop="book|other"] 两套换色与 .t-book / .t-other 文案切换，新增一个 .t-drag。
  • JS：dragenter 抽色（数组五选一），dragover 只更新坐标（不重抽）； drop 沿用条目二的保持/兜底。
  • 会牵动的用例（全部先红后绿，不直接删断言）： case_ui_drop_has_three_states（三态→悬停一态）、 case_ui_drop_classifies_by_mime_only（悬停不再分类，意图作废，改成「悬停期不判书/非书」的用例）、 case_ui_drop_never_guesses_without_mime（意图保留、机械断言随实现换）、 case_ui_drop_uses_no_generic_green_red（改成「五色必须来自封面色板」）、 case_ui_drop_office_docs_are_not_books 与 case_ui_drag_exe_and_json_are_not_books（同上）。
