# bug 修复流程

本文只说流程。**怎么修**由肥鱼定位后与开发者商定，商定的结果写进 `TODO.md`；
**为什么这么修**写不写成决策笔记，按 `docs/notes/` 的判据当场判定。

## 一、bug 从哪来

1. **开发者反馈的**：使用者报给开发者，开发者转给肥鱼。
2. **肥鱼开发时自己发现的**。

## 二、开发者反馈的 bug

1. 开发者把现象说给肥鱼。
2. 肥鱼复现并定位，评估修复难度与影响面，把结论反馈给开发者。
3. 双方商定**这个 bug 在哪个版本修**。版本口径见 `AGENTS.md` 的「版本更新原则」。
4. 把**「这个 bug 将来怎么修」**写进 `TODO.md` 对应条目。

> `TODO.md` 记的是**待办与修法**，不是修复流水账。已经修完的不留在 `TODO.md`。

## 三、肥鱼自己发现的 bug

- 能自己修的直接修（同样要走第五节的验收）。
- 短期修不了的，向开发者反馈并商定版本，写进 `TODO.md`。

## 四、定下修法之后，必须留一道痕

每定下一个 bug 的修法（尤其是与开发者商量出来的），当场判定要不要写成决策笔记，
并在给开发者的汇报里**写明一行**：

```
决策笔记：写 / 不写 + 一句理由
```

不许默默跳过 —— 跳过就没人能发现漏判。
判据在 `docs/notes/`（「新增一篇的判据」）：命中「改判定规则 / 增删依赖例外 / 实现细节被实测推翻」**必写**；
其余看「不写的话，下次开新会话最可能做出什么蠢事」，答得出具体的蠢事才写。
这条规则也写进了 `TODO.md` 总览。

## 五、什么算「修完」

1. 改完代码。
2. 跑对应测试脚本（**逐个直跑，不用 pytest**），再跑 `python -B tools/smoke_test.py`。
3. 把测试结果贴给开发者。
4. 开发者验收，明确说没问题。
5. 从 `TODO.md` 移除该条，按版本归档到私有库 `G:\wish_project\huoban-notes\todo\`。

**没经过第 4 步，不算关闭。** 测试全绿只说明没弄坏别的，不等于 bug 修对了。

## 六、CHANGELOG

单个 bug 修完**当时不写** `CHANGELOG.md`；按版本发版时统一写。

## 七、不许做的事

- 不擅自替开发者定版本号或排期。
- 不默默跳过第四节的「决策笔记」判定。
- 没跑测试就说「修好了」。
- 修完不归档、让已完成的条目一直躺在 `TODO.md` 里。
