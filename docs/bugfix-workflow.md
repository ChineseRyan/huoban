# bug 修复流程

本文只说流程。**怎么修**由肥鱼定位后与开发者商定，商定的结果写进 `TODO.md`；
**为什么这么修**写不写成决策笔记，按 `docs/notes/` 的判据当场判定。

## bug 从哪来

1. **开发者反馈的**：使用者报给开发者，开发者转给肥鱼。
2. **肥鱼开发时自己发现的**。

## 开发者反馈的 bug

1. 开发者把现象说给肥鱼。
2. 肥鱼复现并定位，评估修复难度与影响面，把结论反馈给开发者。
3. 双方商定**这个 bug 在哪个版本修**。版本口径见 `AGENTS.md` 的「版本更新原则」。
4. 把**「这个 bug 将来怎么修」**写进 `TODO.md` 对应条目。

> `TODO.md` 记的是**待办与修法**，不是修复流水账。已经修完的不留在 `TODO.md`。

`TODO.md` 是本机文件，被 `.gitignore` 忽略、不入库——别指望在公开仓库里找到它。

## 肥鱼自己发现的 bug

- 能自己修的直接修（同样要走「什么算『修完』」的验收）。
- 短期修不了的，向开发者反馈并商定版本，写进 `TODO.md`。

## 定下修法之后，必须留一道痕

每定下一个 bug 的修法（尤其是与开发者商量出来的），当场判定要不要写成决策笔记，
并在给开发者的汇报里**写明一行**：

```
决策笔记：写 / 不写 + 一句理由
```

不许默默跳过 —— 跳过就没人能发现漏判。
判据见本节：命中「改判定规则 / 增删依赖例外 / 实现细节被实测推翻」**必写**；
其余看「不写的话，下次开新会话最可能做出什么蠢事」，答得出具体的蠢事才写。
这条规则也写进了 `TODO.md` 总览。
写进 `TODO.md` 的条目是**跨窗口交接单**：修复可能在另一个对话窗口做，那边看不到排查过程。
所以条目必须自带四样，缺一样就算没写完：

1. **根因**：现象由哪一处代码或规则造成；
2. **证据**：实测数字或包结构，不写「应该是」；
3. **不能动的东西**：有意设计、被测试钉住的断言，写清它为什么存在、该拆开还是保留；
4. **验收标准**：拿什么验证、跑哪些脚本、看哪些数字。

`TODO.md` 同一时刻只有一个维护者：**写条目的人负责写，改代码的人不改这份文件**，
完工只向开发者回报。两边同时改，条目会被覆盖。

## 什么算「修完」

**先钉一条回归用例**：加在对应的 `tests/test_<模块>.py`，修之前先跑一次，确认它真的会失败；修完之后必须转绿。只会通过的用例不算证据。

1. 改完代码。
2. 跑对应测试脚本（**逐个直跑**），再跑 `python -B tools/smoke_test.py`。
3. 把测试结果贴给开发者。
4. 开发者验收，明确说没问题。
5. 从 `TODO.md` 移除该条，按版本归档到私有库 `huoban-notes` 的 `todo/`。

**没经过第 4 步，不算关闭。** 测试全绿只说明没弄坏别的，不等于 bug 修对了。
> 分工时按窗口拆：第 1～3 步（改代码、跑测试、贴结果）由**修复窗口**做；
> 第 4 步是开发者；第 5 步（移除条目、归档）由**写条目的窗口**做 ——
> 修复窗口不自己删条目。

## 测试期

**从哪一刻起算**：开发窗口确认「`TODO.md` 里属于当前版本的需求与 bug 已全部解决」时，
**主动**打包一个可用的压缩包交给开发者 —— 不等开发者开口要 —— 从这一刻起进入该版本的测试期。

**测试期发现的 bug**：开发者拿这个测试包用出来的问题，包括

- a. 已有的、没解决的 bug；
- b. 新的 bug；

都反馈给开发窗口，**沿用同一个版本号继续改**，不新占版本号。

**这类 bug 记在哪**：不写进 `TODO.md`，也不进 TODO 的版本存档；
**只写进 `CHANGELOG.md` 该版本的「修复」小节**，不另占版本号。

**但不豁免三件事**：

1. **决策笔记照旧判定并留痕** —— 不进 TODO 不等于免掉那一问（见「定下修法之后，必须留一道痕」）；
2. **修完仍要跑测试**：对应测试脚本逐个直跑 + `python -B tools/smoke_test.py`；
3. **同一个 bug 第二次出现，升级成 `TODO.md` 条目** —— 第一次没留条目，回归时就没地方查历史。

`CHANGELOG.md` 在公开仓库、永久保留：只写用户能感知的现象，
不写站点名、渠道名、公众号名这类细节。

## CHANGELOG

单个 bug 修完**当时不写** `CHANGELOG.md`；按版本发版时统一写。

## 不许做的事

- 不擅自替开发者定版本号或排期。
- 不默默跳过「定下修法之后，必须留一道痕」的「决策笔记」判定。
- 没跑测试就说「修好了」。
- 修完不归档、让已完成的条目一直躺在 `TODO.md` 里。
